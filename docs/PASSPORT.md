# Memory Passport (`memo.passport.v1`)

A **versioned, vendor-neutral** snapshot of a memo durable corpus. The passport
lets your accumulated memory travel — to another machine, another install, or
another tool — without lock-in. It is plain JSON with a stable schema, validated
on import.

> memo already round-trips memo→memo via `memo export json` / `memo import json`.
> The passport adds three things that make it a *portable brain* rather than a
> dump: a stable `schema` header, validation on import, and semantic fidelity
> (type, tags, and the provenance / verification `extra` bag).

## Usage

```bash
memo export passport ~/brain.passport      # write the whole durable corpus
memo import passport ~/brain.passport      # validated, high-fidelity import
```

## Format

Top-level envelope:

```json
{
  "schema": "memo.passport.v1",
  "generator": "memo/3.10.0",
  "exported_at": "2026-07-22T12:00:00+00:00",
  "count": 1,
  "memories": [
    {
      "id": "abcd1234ef",
      "type": "decision",
      "title": "int8 is the default",
      "body": "We ship int8 vec quantization by default.",
      "tags": ["project:memo"],
      "created": "2026-07-01T00:00:00Z",
      "updated": "2026-07-20T00:00:00Z",
      "extra": { "verification_state": "verified", "synthesis_sources": ["…"] }
    }
  ]
}
```

| Envelope field | Meaning |
|---|---|
| `schema` | Must be `memo.passport.v1`. Import rejects any other value. |
| `generator` | Producer + version, informational. |
| `exported_at` | ISO-8601 UTC timestamp of export. |
| `count` | Number of entries in `memories`. |
| `memories` | List of entry objects. |

| Entry field | Round-trips? |
|---|---|
| `type`, `title`, `body`, `tags`, `created` | ✅ preserved verbatim |
| `extra` (provenance, verification state) | ✅ preserved verbatim |
| `id`, `updated` | ♻️ regenerated by the receiving store |
| embeddings, graph relations | ♻️ rebuilt on import + reindex (derived data) |

## Fidelity contract

The passport carries the **canonical** record — what markdown is the source of
truth for (see the repo's "markdown is source of truth; sqlite is a rebuildable
index" invariant). Derived indexes (embeddings, graph edges) are **not** shipped
in v1: they are rebuildable, and omitting them keeps the passport small and
vendor-neutral. The receiving store re-derives them on import. Ids are
regenerated on the target — relations are re-derived, so identity by content and
provenance survives, identity by id does not.

Everything a human authored — content, type, tags, created, and the
provenance / verification `extra` bag — round-trips exactly.

## Consuming from another tool

The format is plain JSON: any tool can read `memories[]` and map the entry
fields into its own model. `type` and `tags` give structure; `extra` carries
provenance. Validate `schema == "memo.passport.v1"` before trusting the shape.
